Codex Quota Widget Recipe

Capability

Add a baby-menu widget that shows Codex usage limits, credits, and reset windows from local Codex credentials or CLI state.

The widget should prefer real local data and fall back to clearly labeled mock data only when no usable source is available.

This recipe is self-contained. Do not require external source code, websites, or implementation guides to complete it.

User-Facing Behavior

  • Show primary and secondary Codex usage windows when available.
  • Show reset countdown or reset timestamp for each window when available.
  • Show credit balance if available.
  • Show account email and plan type if available.
  • Show last refreshed time.
  • Show loading, success, stale, unavailable, and error states.
  • Refresh automatically every 5 minutes by default.
  • Expose a manual refresh button.

Recommended Data Source Order

PrioritySourceUse WhenExpected Data
1 Codex OAuth usage API ~/.codex/auth.json or $CODEX_HOME/auth.json contains usable OAuth credentials. Rate limit windows, reset timestamps, account identity, plan hints, credit snapshot when available.
2 Codex CLI RPC app server The codex CLI is installed and signed in. Rate limit windows, credits, account identity.
3 Manual status parser A developer supplies saved codex /status output for tests or diagnostics. Credits, five-hour limit, weekly limit, reset text.
4 Mock provider No real source is configured or readable. Static sample values labeled Mock data.

OAuth Usage API Details

Credential locations to check from codex-quota/server.ts only:

  • $CODEX_HOME/auth.json if CODEX_HOME is set.
  • ~/.codex/auth.json otherwise.

Request:

GET https://chatgpt.com/backend-api/wham/usage
Authorization: Bearer <access_token>

If the token metadata includes a refresh timestamp and it is older than roughly 8 days, prefer returning a sign-in or refresh-needed error for the first implementation rather than silently using a stale token.

Normalize response data into this shape:

type CodexQuotaSnapshot = {
  source: "oauth" | "cli-rpc" | "status-text" | "mock";
  accountEmail?: string;
  plan?: string;
  windows: Array<{
    id: "five_hour" | "weekly" | "primary" | "secondary";
    label: string;
    percentUsed?: number;
    percentRemaining?: number;
    resetText?: string;
    resetAt?: string;
  }>;
  credits?: {
    balance?: number;
    hasCredits?: boolean;
    unlimited?: boolean;
  };
  refreshedAt: string;
  stale: boolean;
};

Codex CLI RPC Details

Run privileged CLI work in codex-quota/server.ts behind window.babyMenu.capabilities.invoke. Do not expose Node APIs to the renderer.

Command:

codex -s read-only -a untrusted app-server

JSON-RPC flow over stdin/stdout:

  1. Send initialize with a simple client name and version.
  2. Send account/read to get account identity when available.
  3. Send account/rateLimits/read to get windows and credits.
  4. Terminate the child process after the request.

Timeouts:

  • Allow up to 15 seconds for app-server startup and initialize.
  • Allow up to 8 seconds per normal RPC method.
  • Kill the child process on timeout so future refreshes are not blocked.

Expected data:

  • Usage windows may arrive as primary/secondary or five-hour/weekly equivalents.
  • Credit data may include balance, hasCredits, and unlimited flags.
  • Account identity may include email and plan type.

Status Text Parser Details

Do not launch the interactive Codex TUI in the background for the first implementation.

Keep this parser for tests and manual diagnostics using captured /status text.

Parser expectations:

  • Strip ANSI escape sequences.
  • Parse Credits: lines into credits.balance where possible.
  • Parse 5h limit lines into a five-hour usage window.
  • Parse Weekly limit lines into a weekly usage window.
  • Extract percent used or remaining and reset text near each line.
  • Surface update prompts as Codex CLI update needed.

Optional Web Dashboard Extras

Do not implement browser-cookie scraping in the first widget unless the user explicitly asks for richer dashboard extras.

If implemented later, it must be opt-in and server-action only.

Dashboard URL: https://chatgpt.com/codex/settings/usage.

Potential extras include code review remaining, usage breakdown chart data, credits history, and credits purchase URL.

Cookie handling must never write secrets to committed files or renderer logs.

Implementation Contract

Create or edit these extension files:

  • codex-quota/server.ts for privileged token, CLI RPC, timeout, and parser work.
  • codex-quota/widget.tsx for a RefreshableBabyMenuWidget, using @babymenu/ui.
  • The widget should call window.babyMenu.capabilities.invoke("codex-quota", "getQuota", input).
  • Put quota reload logic in the widget's exported refresh method and set refreshIntervalMs to 5 minutes; WidgetHost owns timer and manual refresh calls.
  • Do not add preload methods, per-widget IPC channels, core renderer widgets, or WidgetHost registration; Baby Menu discovers extension widgets automatically.

Add repo-level tests:

  • tests/codex-quota.test.ts for parser, RPC fallback, timeout, and mock tests.

Server action response shape:

type QuotaResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: string; sourceTried: string[]; mock?: T };

Error Handling

  • If no auth file or CLI is available, show Codex quota unavailable and offer mock data labeled as mock.
  • If the CLI app-server times out, show Codex CLI timed out and keep the previous successful value as stale.
  • If credentials are expired, show Codex sign-in required.
  • If macOS blocks the CLI executable, show Codex CLI could not be launched.
  • Never print token or cookie values in renderer errors, logs, or tests.

Acceptance Criteria

  • The widget displays current Codex quota state or a clear unavailable state.
  • The widget displays source label: OAuth, CLI RPC, Status text, or Mock data.
  • The widget displays when it was last refreshed.
  • The widget refreshes on a timer.
  • The widget exposes a manual refresh action.
  • The widget shows stale previous values if a refresh fails after a prior success.
  • The widget shows a clear error state if quota cannot be read.
  • Tests cover status parser success, parser missing data, CLI timeout/error fallback, and mock fallback.
