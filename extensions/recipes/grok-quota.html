Grok Quota Widget Recipe

Capability

Show the official consumer Grok usage pool, product breakdown, reset, and Extra Usage Credits through the exact consumer Usage-page operation.

The sole quota source is grok_api_v2.GrokBuildBilling.GetGrokCreditsConfig at https://grok.com/grok_api_v2.GrokBuildBilling/GetGrokCreditsConfig.

Use the provider-owned ~/.grok/auth.json bearer and let only the official client refresh an expired or rejected session.

Do not run a healthy-session CLI preflight, import browser cookies, call the CLI billing proxy, call ACP billing, implement OAuth, or calculate quota from money.

This recipe is self-contained and requires no external implementation guide.

Recommended Data Source Order

PrioritySourceContract
1Exact consumer gRPC-web operationFresh official percentages, period, reset, products, and prepaid balance.
2Conditional official client refreshOnly after local expiry or one credential-classified consumer response, followed by auth reread and one retry.
3Principal-bound schema version 2 cacheSame-account last-good data for eligible transient failures only.

The CLI billing proxy and monetary fields are never parser fallbacks.

quota-axi may be used as optional development evidence, but it is never a runtime dependency or oracle.

Read-only Auth Selection

Credential access belongs only in grok-quota/server.ts.

Resolve auth in this order: $GROK_AUTH_JSON, $GROK_AUTH_PATH, $GROK_HOME/auth.json, then ~/.grok/auth.json.

The auth file is an object keyed by provider scope, and a usable entry must contain a non-empty string key.

  1. Prefer a current entry whose scope begins with https://auth.x.ai::.
  2. Use a current https://accounts.x.ai/sign-in or compatible sign-in entry only when no current OIDC entry exists.
  3. Ignore unrelated and API-key-shaped scopes even when their expiry is later.
  4. Select an expired OIDC or legacy entry only to drive one conditional official-client refresh when no current supported entry exists.
  5. Return auth_scope_ambiguous before network access when current entries in the winning class bind to different or unknown principals.

Build an internal SHA-256 account binding from non-secret principal type, user id, and team id fields.

Never return the account binding, raw ids, email, scope string, auth contents, or bearer to the renderer or diagnostics.

If no stable account binding can be formed, fresh data may render, but persistent last-good data must not be written or reused.

Classify auth sources exactly: a missing resolved file is auth_source_missing; a permission, I/O, or other read failure is auth_source_unreadable; invalid JSON is auth_source_malformed; and no usable credential is auth_source_incompatible.

Do not run a CLI capability probe for missing, unreadable, malformed, incompatible, ambiguous, or healthy auth.

Do not classify these local source outcomes as parse_incompatible or sign-in-required.

Conditional Official-client Refresh

The installed official client documents grok models as "List available models and exit," so it is a bounded non-prompt capability that exercises the client's own auth manager.

Invoke it only when the deterministically selected bearer is locally expired or when one exact-source request returns HTTP 401, gRPC 16, or a narrowly recognized credential-like gRPC 7 message.

HTTP 403 remains a rejected credential or permission outcome but does not trigger refresh.

Never invoke it before every acquisition, after permission or team-scope failures, or after the one post-refresh retry.

Spawn the discovered executable with argument array ["models"], shell: false, ignored stdin, the complete inherited environment, a 20-second timeout, and 128 KiB bounded stdout and stderr held only in memory.

Discover $GROK_CLI_PATH, $GROK_HOME/bin/grok, current PATH, home-local Grok locations, then Homebrew locations without a shell.

After exit zero, reread the same resolved auth source, apply deterministic OIDC-over-legacy selection again, and require the new stable account binding to equal the pre-refresh binding.

Return auth_principal_changed without a gRPC retry when the principal changes, and return auth_expired when official refresh leaves the selected bearer expired.

A successful continuity check permits exactly one new GetGrokCreditsConfig request with the reread bearer.

Never read, post, or exchange a refresh token directly, and never infer success from CLI output.

An immutable $GROK_AUTH_JSON override cannot be refreshed by the client and must fail explicitly when expired.

Exact gRPC-web Request

POST https://grok.com/grok_api_v2.GrokBuildBilling/GetGrokCreditsConfig
Authorization: Bearer <selected key>
Accept: */*
Content-Type: application/grpc-web+proto
Origin: https://grok.com
Referer: https://grok.com/?_s=usage
x-grpc-web: 1
x-user-agent: connect-es/2.1.1

00 00 00 00 00

The five body bytes are one empty uncompressed gRPC-web data frame.

Do not send x-grok-client-mode: billing.

Do not call GET https://cli-chat-proxy.grok.com/v1/billing?format=credits or _x.ai/billing.

Apply one 15-second whole-request deadline and a 64 KiB streamed response cap.

Reject oversized, truncated, malformed, compressed, and multiple-data-frame responses before typed protobuf normalization.

Validate grpc-status from both HTTP headers and gRPC-web trailer frames.

Retry exactly once only for bounded transport failures, HTTP 408/502/503/504, gRPC deadline exceeded, or an explicit timeout or cancellation status.

Never retry authentication, permission, team scope, parser, schema, or response-size failures.

Typed Protobuf Decoder

Accept one valid framed data payload or the provider's compatible raw protobuf payload.

Use a bounded typed decoder for these exact proto3 fields:

MessageFieldWire typeMeaning
Response1messageconfig
Config1fixed32creditUsagePercent
Config7repeated messageproductUsage
Config8messagecurrentPeriod
Config12messageprepaidBalance
Product usage1 / 2varint / fixed32Product enum / used percentage
Usage period1 / 2 / 3varint / timestamp / timestampType / start / end
Cent1varintBalance value

Map product enum 1 through 6 to API, Grok Build, Grok Plugins, Chat, Imagine, and Voice.

Preserve exact finite used percentages after clamping to 0..100, and derive remaining as 100 - percentUsed.

Use only config.currentPeriod.end as a quota reset.

A valid monthly or weekly current period plus an omitted global proto3 float is an official zero-percent success with omittedProto3Default: true.

A structurally valid product entry with an omitted product float is an official product zero with the same provenance marker.

Without an explicit official percentage or valid current-period evidence, return quota_unreported rather than inventing zero.

Never divide config.used.val by config.monthlyLimit.val, onDemandUsed by onDemandCap, or derive quota from history, prepaid balance, elapsed time, or billing dates.

Normalized Types

type GrokQuotaSnapshot = {
  schemaVersion: 2;
  source: "grok-credits-grpc-web";
  sourceVersion: 1;
  operation: "grok_api_v2.GrokBuildBilling.GetGrokCreditsConfig";
  accountBinding: string; // storage only, never renderer output
  period: {
    type: "weekly" | "monthly" | "unspecified";
    startAt?: string;
    endAt?: string;
    provenance: "config.currentPeriod";
  };
  windows: Array<{
    id: "credits" | `product:${string}`;
    label: string;
    percentUsed: number;
    percentRemaining: number;
    resetAt?: string;
    provenance: {
      percentageField: "config.creditUsagePercent" | `config.productUsage[${number}].usagePercent`;
      resetField?: "config.currentPeriod.end";
      omittedProto3Default?: true;
    };
  }>;
  credits?: {
    remaining: number;
    unit: "credits";
    sourceField: "config.prepaidBalance.val";
  };
  refreshedAt: string;
  stale: boolean;
};

    | "auth_source_unreadable"
    | "auth_source_malformed"
    | "auth_source_incompatible"
    | "credential_rejected"
    | "cli_not_found"
    | "cli_launch_failed"
    | "connectivity"
    | "rate_limited"
    | "quota_service"
    | "official_quota_source_unavailable"
    | "team_scope_unsupported"
    | "response_too_large"
    | "quota_unreported"
    | "parse_incompatible";
  message: string;
  sourcesTried: Array<"local-auth" | "consumer-quota-api" | "grok-cli-refresh" | "cache">;
  httpStatus?: number;
  grpcStatus?: number;
  retryAt?: string;
  diagnostic?: string;
};

type GrokQuotaResult =
  | { ok: true; checkedAt: string; data: Omit<GrokQuotaSnapshot, "accountBinding">; warning?: QuotaFailure }
  | { ok: false; checkedAt: string; failure: QuotaFailure };

Implementation Contract

All auth, network, protobuf, and cache work belongs in grok-quota/server.ts behind window.babyMenu.capabilities.invoke.

Use context.db for one internal last-good snapshot.

Cache trust boundary: only schema version 2, source grok-credits-grpc-web, source version 1, the exact operation, complete field provenance, and an equal current account binding are trusted.

Unversioned, schema version 1, future-version, malformed, wrong-source, wrong-operation, provenance-free, and wrong-principal rows are untrusted.

Delete the rejected row instead of rewriting, inferring, or promoting it.

Only a successful exact-source response may write schema version 2.

On an eligible transport, service, or conditional refresh failure, return a same-principal trusted row as stale without changing the stored bytes.

Auth ambiguity, auth expiry, principal change, unsupported team scope, and an unbound identity must not render another principal's cache.

Single-flight the entire getQuota acquisition so startup, interval, and manual calls share one request and one cache write.

Server action response shape is the GrokQuotaResult union above.

Renderer and Refresh Contract

Export a RefreshableBabyMenuWidget with a five-minute viewRefreshIntervalMs and one shared refreshView function.

The host-owned refreshView call is the startup refresh, so do not launch a mount-time request.

The visible manual refresh control must call the same function, disable itself while pending, and never create overlapping work.

While refresh is pending, keep the currently rendered successful windows and show an updating indicator.

Every completion must expose a fresh safe checkedAt and update the visible last checked state.

One rendered widget root must own the complete stable observability contract below in waiting, success, and failure states.

These attributes are a machine-readable mirror of the normalized renderer state, while the visible UI remains the user-facing truth.

Every listed attribute must exist directly on the same data-grok-e2e root in every state; use the documented empty values rather than omitting attributes or nesting aliases under children.

A waiting root has no completed result, so it must use the documented empty parity values and data-grok-completed-acquisitions="0". Never replace a completed success or failure root with waiting during interval or manual refresh.

The unattended harness validates this complete root contract for generated and future managed widgets.

A terminal partial root is an explicit observability failure, not an intermediate state to poll until timeout.

Hidden observability values are limited to the non-secret normalized values already allowed in renderer state.

Never place account binding, user or team ids, auth values, scopes, headers, raw protobuf, raw provider payload, or credential-refresh output in the DOM.

Label the shared window Weekly, Monthly, or Credits from the decoded current period.

Show both official used percentage and derived remaining percentage so parity is reviewable.

Round only rendered values, never stored values or provenance.

Render products only from product entries in the same response and reset only from config.currentPeriod.end.

Show sign-in guidance only for an actual authentication outcome.

Show distinct actionable copy for auth_expired, auth_scope_ambiguous, team_scope_unsupported, provider, parser, and response-size failures.

Never suggest browser sign-in for official_quota_source_unavailable.

Error Classification

  • HTTP 401/403, gRPC 16, and narrowly recognized credential-like gRPC 7 messages are credential_rejected.
  • Arbitrary gRPC 7 is not authentication.
  • gRPC 9 with the known no-personal-team condition is team_scope_unsupported.
  • HTTP 429 and gRPC resource exhaustion are rate_limited.
  • Network and deadline failures are connectivity.
  • Malformed compatible-status responses are parse_incompatible.
  • Responses over 64 KiB are response_too_large.
  • A response with neither an official percentage nor valid current-period proto3-default evidence is quota_unreported.

Diagnostics are allowlisted status, timeout, and missing-field metadata only.

Raw response data and gRPC messages never leave the server action.

Security Constraints

  • Use the exact bearer request and no browser cookies.
  • Launch only the documented conditional grok models capability and let that official client own credential mutation.
  • Never implement OAuth or pass a credential through process arguments or newly created environment variables.
  • Never log, return, cache separately, or commit tokens, refresh tokens, emails, ids, scopes, headers, raw protobuf, or provider bodies.
  • Never expose the internal account binding to the renderer.
  • Never use another local identity as a fallback after rejection.

Acceptance Criteria

  • The server sends the exact gRPC-web POST, headers, and five-byte body with no client-mode header, cookie, proxy, or ACP path.
  • OIDC selection, legacy fallback, expiry, ambiguity, and unbound identity behavior are deterministic.
  • Local expiry and one credential-classified response run one bounded fake-CLI-tested official refresh, reread auth, verify principal continuity, and issue exactly one gRPC retry.
  • A healthy successful bearer never launches the CLI, and deterministic tests never execute a real Grok binary.
  • The bounded typed decoder covers framed and raw payloads, global and product percentages, current period, prepaid balance, proto3 zero, trailers, malformed data, and the response cap.
  • Exact used values remain unrounded in state and cache, remaining is derived, and rounding occurs only in visible copy.
  • Schema version 1 never renders, and schema version 2 cache reuse requires the same account binding.
  • Startup, interval, and manual refresh preserve renderer-causal single-flight, pending, settle, completion-count, checked-at, stale, and cleanup behavior.
  • Waiting, success, and failure render every stable data-grok-* observability attribute directly on one root with the exact documented values.
  • The generated fixture binds those attributes from renderer state and passes the complete-root observer contract for waiting, success, and failure.
  • The unattended E2E independently calls the same exact operation in the same time window and compares safe operation, account-binding equality, period, global, product, reset, provenance, and lifecycle fields.
  • No credential, cookie, raw principal, account-binding material, header, or raw provider payload appears in logs, renderer data, fixtures, screenshots, or evidence.
