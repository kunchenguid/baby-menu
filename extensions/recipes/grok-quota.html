Grok Quota Widget Recipe

Capability

Source Grok quota and credit windows from Grok's provider-owned local auth, official CLI refresh path, and billing HTTP API.

Do not depend on a separate quota CLI or npm package. Read provider-owned credentials in the server action and call the billing API directly while they are current. When a refreshable session has expired or the billing API rejects it, use the already-installed official Grok CLI only to exercise Grok's own refresh manager, then reread auth and retry once. The official CLI is part of Grok, not a separate quota helper.

The widget must preserve last-good quota as visibly stale during temporary failures, return structured failure kinds when no cache exists, and render accurate failure-specific copy. It must never fabricate quota or collapse every failure into sign-in guidance.

This recipe is self-contained. Do not require external source code, websites, or implementation guides to complete it.

Recommended Data Source Order

PrioritySourceUse WhenExpected Data
1 Local Grok auth file + billing API A current or expiry-unknown credential exists and the billing API accepts it. Official subscription usage percent and current reset period when Grok reports them, with optional product-scoped and prepaid fields.
2 Official Grok CLI auth refresh A selected session is expired, every initial billing candidate is rejected with 401 or 403, or the official client must establish whether a local session is authenticated. A refreshed provider-owned auth file, followed by one reread and one billing retry pass.
3 Cached last-good snapshot Refresh, CLI launch, network, rate-limit, quota-service, or parse work fails. The same quota shape as source 1, marked stale: true with a structured warning.

quota-axi may be used as optional development evidence, but it is never a runtime dependency or refresh authority. Do not exec or require it from the widget. Grok's official CLI owns refresh-token rotation, credential locking, custom auth providers, and retry-on-401 behavior.

Local Auth Details

Read credentials only from grok-quota/server.ts, never from the renderer.

Resolve the auth source in this order:

  1. $GROK_AUTH_JSON - if set, treat its value as inline JSON.
  2. $GROK_AUTH_PATH - if set, treat its value as an explicit auth file path.
  3. $GROK_HOME/auth.json - if GROK_HOME is set.
  4. ~/.grok/auth.json - the default location.

The file is a JSON object keyed by auth-scope identifiers. Each value may have this shape:

{
  "<scope-key>": {
    "key": "<bearer-token>",
    "auth_mode": "oidc",
    "email": "user@example.com",
    "expires_at": "2026-07-09T18:48:56.527168Z",
    "refresh_token": "..."
  }
}

Iterate every object entry instead of hardcoding a scope key. Collect entries with a non-empty string key. Classify an entry as a refreshable session when it has a non-empty refresh_token and/or session-shaped auth_mode; otherwise treat it as API-key-shaped.

Order candidates by current session, expiry-unknown session, current API key, expiry-unknown API key, then expired entries. An invalid or missing expires_at is unknown, not expired. A local expiry timestamp is a refresh-needed hint, not proof that the user is signed out.

When the selected session credential is expired, invoke the official Grok CLI refresh path before the billing request. If another non-expired candidate can satisfy the request, it is safe to try that candidate first, but never discard the expired session or turn its timestamp directly into auth_required.

After a successful official refresh, reread the same resolved auth source from disk and rebuild candidates. Never retain or retry the pre-refresh bearer token by accident. If GROK_AUTH_JSON is used, reread that override consistently; an immutable expired inline override may correctly end as a refresh failure rather than falling through to a different secret source.

Preserve the exact local auth outcome: a missing resolved file is auth_source_missing; a permission, I/O, or other read failure is auth_source_unreadable; invalid JSON is auth_source_malformed; and a parsed value with an incompatible top-level shape or no usable credential is auth_source_incompatible. Apply the same malformed and incompatible distinction to GROK_AUTH_JSON. Do not collapse these outcomes into parse_incompatible or infer sign-out from any of them.

When local auth cannot produce a candidate, run the bounded official CLI capability probe at most once for that getQuota call, using the same single-flight refresh path, then reread and reclassify the resolved auth source. Return auth_required only when that probe exits with an explicit verified authentication-required marker. If the probe succeeds but reread still cannot produce a candidate, return the precise post-probe auth-source outcome. If the probe cannot be found or fails without a verified authentication marker, return its structured CLI failure instead of guessing that sign-in is required.

Read the optional client version from $GROK_HOME/version.json or ~/.grok/version.json. Use its non-empty version for x-grok-client-version. Omit the header when unavailable instead of guessing.

Never log, echo, cache separately, or return a bearer token, refresh token, email, auth scope, raw auth file, request header, or response body.

Official Grok Refresh Path

Use the documented non-interactive grok models command to exercise the official auth manager. It may refresh an OIDC session before expiry or after an authenticated provider response. Inspect the installed command's real help and sanitized exit behavior before implementation, then verify this exact command against the installed version without printing its output.

Never implement the OIDC refresh-token exchange directly. Do not post refresh_token yourself. Grok owns provider selection, rotating refresh tokens, locking, enterprise configuration, and token persistence.

Discover an executable file in this order without a shell:

  1. $GROK_CLI_PATH when it is an explicit executable file.
  2. $GROK_HOME/bin/grok when GROK_HOME is set.
  3. Each current PATH directory joined with grok.
  4. ~/.local/bin/grok.
  5. ~/.grok/bin/grok.
  6. /opt/homebrew/bin/grok.
  7. /usr/local/bin/grok.

Do not rely only on an interactive shell's PATH. Baby Menu expands process.env.PATH for GUI launches, but explicit home-directory and Homebrew candidates are still required. Check executable access and deduplicate resolved paths.

Run the resolved executable with execFile or spawn, argument array ["models"], shell: false, ignored stdin, a hard timeout around 20 seconds, and bounded stdout and stderr. On timeout, kill the child on timeout and wait for it to close before settling the shared promise. Never interpolate paths into a command string.

When constructing the child environment, preserve the complete inherited process.env and add only safe presentation overrides such as NO_COLOR=1 and TERM=dumb. Do not rebuild a narrow environment that drops HOME, GROK_HOME, proxy settings, deployment endpoints, enterprise OIDC configuration, API-key configuration, or custom auth-provider settings.

Exit zero means the official capability probe completed. Always reread the auth source after the command succeeds, even if stdout is empty or changes format, because the useful result is the official side effect on provider-owned auth. For nonzero exit, inspect output only in memory and map only verified, allowlisted authentication markers to auth_required. Every unknown nonzero exit is cli_launch_failed, not a sign-in conclusion. Return only a safe exit code, timeout flag, or searched path categories as diagnostics, never raw output.

Keep a module-scope single-flight promise so concurrent widget refreshes share one official CLI process. Each acquisition also keeps a local refreshAttempted boolean. Clear the CLI single-flight promise when it settles, add a short cooldown after failure, and never launch a duplicate refresh during the same request.

Separately single-flight the entire getQuota acquisition, not only the CLI subprocess, so concurrent startup, interval, and manual calls share one billing request and one cache write even when the credential is already current.

Billing API Details

Request:

GET https://cli-chat-proxy.grok.com/v1/billing?format=credits
Authorization: Bearer <key>
Accept: application/json
x-grok-client-mode: billing
x-grok-client-version: <version>   (optional, omit if unknown)

Grok's installed ACP agent exposes the same account data through _x.ai/billing. Treat that bounded, sanitized official-client response as the official Grok UI source of truth during implementation and end-to-end verification. The direct credits request may remain the lightweight runtime path only while its normalized percentage and reset agree with the official client.

Do not use the unformatted /v1/billing response to invent a subscription quota. Its config.monthlyLimit.val and config.used.val describe a pay-as-you-go monetary spending cap and spend. A quota widget must not divide config.used.val by config.monthlyLimit.val, label the result as credits, or use its monthly billing period as the subscription reset.

Use a hard timeout around 15 seconds. Try every reasonable candidate in an initial pass. A 401 or 403 rejects that candidate but is not yet an authentication conclusion.

After every candidate in the initial pass returns 401 or 403, invoke the official refresh path once, reread auth, and retry the billing candidate pass exactly once. Never recurse from the retry path, and never refresh again after the retry pass. Return auth_required only when the official CLI itself produces an explicit, verified authentication-required outcome. If the official CLI exits successfully but every candidate in the one allowed retry pass is still rejected with 401 or 403, return credential_rejected; this is a terminal structured outcome for the request and must not launch another probe or show sign-in guidance.

A 429 is rate_limited; parse Retry-After into retryAt when possible. Network errors, DNS failures, TLS failures, aborts, and timeouts are connectivity. A 5xx is quota_service. Other incompatible or unsupported non-auth statuses are quota_service with an allowlisted HTTP status. Never include a body in the diagnostic.

Verified official structural response shape from _x.ai/billing and the credits endpoint on 2026-07-14:

{
  "config": {
    "currentPeriod": {
      "type": "USAGE_PERIOD_TYPE_WEEKLY",
      "start": "<ISO timestamp>",
      "end": "<ISO timestamp>"
    },
    "creditUsagePercent": <optional finite number>,
    "productUsage": <optional array>,
    "onDemandCap": { "val": <finite number> },
    "onDemandUsed": { "val": <finite number> },
    "prepaidBalance": { "val": <finite number> },
    "billingPeriodStart": "<ISO timestamp>",
    "billingPeriodEnd": "<ISO timestamp>"
  }
}

This structural example intentionally contains no account values, identifiers, subscription label, token data, or raw provider payload.

Live output is authoritative. Inspect the official ACP result and direct credits response before writing the parser. Tolerate added fields and missing optional product or prepaid fields, but do not guess a missing usage percentage.

A finite config.creditUsagePercent maps to the global credits window. Clamp it to 0..100, derive remaining as 100 - percentUsed, and use config.currentPeriod.end as the preferred reset with config.billingPeriodEnd as fallback.

Each valid config.productUsage[] entry may add a product window. Its percentage must agree with the official result and must never be synthesized from monetary spend.

A known current-period response that omits every quota percentage is quota_unreported, not a successful zero or monetary quota, not auth_required, and not generic parser drift. Preserve a last-good snapshot as stale with accurate copy that the official Grok source currently reports no quota percentage. With no cache, show that explicit unavailable state.

A malformed or unknown incompatible 2xx response is parse_incompatible. It is never an authentication failure. Do not fabricate zero usage.

Only a successful response with an official percentage may replace the last-good cache, update refreshedAt, and clear stale and warning state.

percentUsed is always percent used. Remaining is 100 - percentUsed. Labels, values, meters, and reset copy must all describe the same official quota window.

Normalized Types

type GrokQuotaSnapshot = {
  source: "api";
  plan?: string;
  windows: Array<{
    id: "credits" | `product:${string}`;
    label: string;
    kind?: "credits";
    percentUsed: number;
    percentRemaining?: number;
    resetAt?: string;
  }>;
  credits?: { remaining?: number; unit?: string };
  refreshedAt: string;
  stale: boolean;
};

type QuotaFailure = {
  kind:
    | "auth_required"
    | "auth_source_missing"
    | "auth_source_unreadable"
    | "auth_source_malformed"
    | "auth_source_incompatible"
    | "credential_rejected"
    | "cli_not_found"
    | "cli_launch_failed"
    | "connectivity"
    | "rate_limited"
    | "quota_service"
    | "quota_unreported"
    | "parse_incompatible";
  message: string;
  sourcesTried: Array<"local-auth" | "billing-api" | "grok-cli-refresh" | "cache">;
  httpStatus?: number;
  retryAt?: string;
  diagnostic?: string;
};

type GrokQuotaResult =
  | { ok: true; data: GrokQuotaSnapshot; warning?: QuotaFailure }
  | { ok: false; failure: QuotaFailure };

Diagnostics are allowlisted metadata only. Safe examples are an exit code, timeout, HTTP status, missing field names, and searched path categories. Unsafe examples are raw stderr, stdout, response bodies, headers, tokens, emails, ids, auth scopes, and auth file contents.

Implementation Contract

All acquisition belongs in grok-quota/server.ts: auth resolution, executable discovery, official refresh, billing requests, cache access, timeouts, parsing, and safe failure classification. Expose getQuota through window.babyMenu.capabilities.invoke("grok-quota", "getQuota", input). Do not add preload methods, per-widget IPC channels, core widgets, or WidgetHost registration.

Use context.db for one last-good snapshot without credentials. On every successful live parse, replace that snapshot. On any later failure, read the last-good snapshot before returning any failure. If one exists, return ok: true, keep its original refreshedAt, set stale: true, and attach the current structured failure as warning.

Refresh failures, CLI discovery or launch failures, connectivity failures, rate limits, quota-service failures, and parse failures all use this stale-cache path. When no last-good snapshot exists, return the structured failure instead. Never erase the last-good row because a refresh failed.

The data is safe to refresh about every five minutes while visible. Export a RefreshableBabyMenuWidget with viewRefreshIntervalMs and refreshView. Do not add background polling or a recursive timer.

The host-owned refreshView call is the startup refresh on the first visible menu show after app launch and on every later popover reopen. Do not launch a second mount-time request from the component or store.

Before implementation, inspect only metadata from real auth, the installed CLI's sanitized behavior, and the real billing response. Before reporting done, verify fresh, expired-refresh, stale-cache, no-cache, authentication, connectivity, and parse outcomes through the actual server action and renderer. Never print secrets while testing.

Server action response shape is the GrokQuotaResult union above. Do not retain the old string-only error result.

Renderer Contract

The renderer must use failure.kind and failure.message instead of replacing every failure with static sign-in copy. Show sign-in guidance only for auth_required. A local expiry timestamp or raw billing 401/403 alone must never produce sign-in guidance.

While a refresh request is in flight, retain the currently rendered successful windows and keep them visibly displayed until the request settles. Show an updating indicator alongside those windows, but never replace them with a blank, unavailable, or loading-only state during CLI, auth reread, billing, or parse work. If the request then fails, continue showing those same windows through the stale-success result and its warning.

For stale success, the widget must keep rendering the cached windows and show that the values are stale, including the original refresh time and an outcome-specific warning. Examples include "Showing cached quota - Grok CLI could not refresh the session", "Showing cached quota - Grok billing is temporarily unreachable", "Showing cached quota - official Grok billing reports no quota percentage", and "Showing cached quota - Grok billing response changed".

For no-cache failure, provide distinct actionable copy: sign in only for auth_required; report the precise local auth source problem for auth_source_missing, auth_source_unreadable, auth_source_malformed, or auth_source_incompatible; say that refreshed credentials were rejected and offer retry for credential_rejected; install or repair the official CLI for cli_not_found or cli_launch_failed; check connectivity for connectivity; wait until retryAt for rate_limited; retry later for quota_service; explain that the official source reports no percentage for quota_unreported; and update the widget for parse_incompatible.

The visible manual refresh control must call the same refresh function used by refreshView, retain the current successful snapshot while pending, and disable itself while that shared request is pending. Repeated presses must not create overlapping billing or CLI work.

Keep a retry control for all failure and stale states. Do not display diagnostics intended only for safe support metadata unless the UI has an explicit details treatment.

Error and Unavailable Handling

  • An expired refreshable session triggers one official refresh, auth reread, and billing attempt. Refresh failure uses stale cache or returns the corresponding CLI failure.
  • Initial billing 401/403 across candidates triggers one official refresh and one retry pass. When a successful probe is followed by another all-candidate rejection, return credential_rejected without another refresh; it is not auth_required.
  • A missing CLI is cli_not_found. Spawn errors, non-auth nonzero exits, and timeouts are cli_launch_failed.
  • DNS, TLS, network, abort, and request timeout failures are connectivity.
  • 429 is rate_limited. 5xx and other provider-service failures are quota_service.
  • A recognized official current period without any reported quota percentage is quota_unreported. It must never be converted from monetary spend or shown as a fresh percentage.
  • Missing, unreadable, malformed, and incompatible auth retain distinct auth-source outcomes after one bounded official probe. A malformed usable 2xx billing response is parse_incompatible. None is sign-in-required without an explicit verified CLI authentication outcome.
  • Every failure first checks cache. Stale data remains visible with its warning; no cache returns ok: false.
  • Invalid reset timestamps are omitted while valid quota remains visible.

Security Constraints

  • Credential, filesystem, process, and network access belongs only in extension-owned server actions behind window.babyMenu.capabilities.invoke.
  • Never commit secrets, token dumps, local auth contents, provider response bodies, or captured command output.
  • Never send Grok credentials or raw provider diagnostics to the renderer. Send only normalized quota and allowlisted failure metadata.
  • Never pass a credential in CLI arguments or environment variables created by the widget. Inherit the existing environment so the official client can use its own supported configuration.

Acceptance Criteria

  • The extension obtains official subscription usage through _x.ai/billing or the matching credits endpoint, verifies the normalized percentage and reset agree, and never requires quota-axi or another quota helper.
  • An expired refreshable session invokes grok models, rereads auth, and makes at most one post-refresh billing pass.
  • An initial all-candidate 401/403 result invokes one shared official refresh and one retry pass without recursion or duplicate processes.
  • Startup, interval, and manual refresh share one whole-acquisition single-flight, and the manual control is disabled while it is pending.
  • Executable discovery works with a constrained GUI launch environment and preserves the inherited child environment.
  • Last-good quota remains visible while refresh is in flight and remains visible as stale for refresh, CLI, connectivity, rate-limit, quota-service, and parser failures.
  • No-cache outcomes preserve accurate structured kinds, and only official CLI evidence can produce auth_required.
  • The renderer shows failure-specific or stale-specific copy and never replaces every result with a sign-in message.
  • Malformed auth, malformed billing responses, and monetary monthly spend never fabricate zero quota, a subscription percentage, reset copy, or sign-in state.
  • No token, refresh token, auth content, raw output, header, or response body is logged, returned, committed, cached separately, or exposed to the renderer.
  • The finished generated extension is verified through Baby Menu's actual server-action and widget install path in a clean environment before reporting done.
