GitHub Copilot Quota Widget Recipe

Capability

Source GitHub Copilot quota windows from the local machine for a baby-menu widget.

Use real local Copilot data through quota-axi only. When quota-axi is missing, Copilot is not signed in, or the live source cannot be parsed, return an unavailable or sign-in-required result - do not fabricate or fall back to mock data.

Scope: this recipe covers only how to obtain and normalize the data. How the widget presents it - layout, states, copy, refresh controls - is left to the implementer and is intentionally not specified here.

This recipe is self-contained. Do not require external source code, websites, or implementation guides to complete it.

quota-axi Source Details

Run privileged CLI work in copilot-quota/server.ts behind window.babyMenu.capabilities.invoke. Do not expose Node APIs to the renderer.

Command:

quota-axi --provider copilot --json

quota-axi must be on PATH. Use a controlled child process, capture stdout, parse JSON, and use a hard timeout around 15 seconds for the first implementation. Treat a non-zero exit, invalid JSON, missing provider, or authentication failure as an explicit unavailable or sign-in-required result. Do not silently substitute sample data.

The shared envelope is always schema version 2:

{
  "generatedAt": "2026-07-09T04:07:26.909Z",
  "schemaVersion": 2,
  "providers": [ /* one provider when --provider is scoped */ ]
}

Take the first matching providers[] entry whose provider is "copilot". Ignore providers with a different id, even if they appear in the envelope.

Verified live output shape from quota-axi --provider copilot --json on 2026-07-09:

Live output is authoritative. Parse defensively: tolerate added fields, missing optional fields, missing windows, non-numeric percentages, and unknown window ids. Do not default a missing percentUsed to 0. Omit a window that has no numeric usage percentage.

Reset timestamp rule. Some Copilot resetsAt values may be epoch-zero placeholders such as 1970-01-01T00:00:00.000Z. Treat non-useful reset timestamps defensively: keep the quota percentage but omit reset text instead of showing 1970.

One axis, consistently. percentUsed is percent used from 0 to 100. Remaining is 100 - percentUsed, or the provided percentRemaining when present and numeric. Whatever the widget chooses to show, the label, number, and any meter for a given window must all describe the same axis.

Normalized Snapshot Type

Normalize quota-axi data into this server action result shape:

type CopilotQuotaSnapshot = {
  source: "quota-axi";
  provider: "copilot";
  label: "GitHub Copilot";
  plan?: string;
  windows: Array<{
    id: "chat" | "completions" | "premium_interactions" | string;
    label: string;
    kind?: "monthly" | string;
    percentUsed: number;          // canonical, percent USED (0-100)
    percentRemaining?: number;    // optional, derive as 100 - percentUsed when absent
    resetAt?: string;             // omit epoch-zero or otherwise non-useful timestamps
  }>;
  refreshedAt: string;
  generatedAt?: string;
  stale: boolean;
  status?: string;
  sourcesTried: string[];
};

Clamp numeric percentages to the inclusive range 0..100. Preserve unknown windows rather than dropping them when they have a usable percentage, since quota-axi may add new Copilot quota windows later.

Implementation Contract

All data acquisition lives in copilot-quota/server.ts: command discovery, child process execution, timeouts, JSON parsing, and any local auth diagnostics. Expose it as a getQuota server action invoked from the renderer with window.babyMenu.capabilities.invoke("copilot-quota", "getQuota", input). Do not add preload methods, per-widget IPC channels, core renderer widgets, or WidgetHost registration; Baby Menu discovers extension widgets automatically.

The data is safe to refresh roughly every 5 minutes while the widget is visible. Use viewRefreshIntervalMs or refreshView for visible refresh. Do not add a background task unless the user explicitly asks for quota monitoring while the popover is closed.

Before writing the parser, inspect real quota-axi --provider copilot --json output on the machine to confirm the current schema version, provider id, window ids, placeholder reset behavior, and state fields. Before reporting the work done, invoke getQuota or an equivalent one-off check against the same command and confirm live, unavailable, and stale paths behave as expected.

Server action response shape:

type QuotaResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: string; sourceTried: string[] };

Error and Unavailable Handling

These are data outcomes the server action returns, not UI copy.

  • If quota-axi is not on PATH, return an unavailable error such as Copilot quota unavailable with sourceTried: ["quota-axi"].
  • If quota-axi reports missing or expired Copilot authentication, return Copilot sign-in required. Do not return mock data.
  • If the command times out or the network is temporarily unavailable, return the previous successful snapshot marked stale: true when one exists.
  • If schemaVersion is not 2 or no matching provider is present, return an unavailable parsing error rather than guessing.
  • Ignore reset timestamps that cannot be parsed or are epoch-zero placeholders. Keep the quota percentage and omit reset text instead of showing a misleading date.
  • Never log, echo, or return token, cookie, or local auth values in errors or logs.

Local Auth Diagnostics

These details are for troubleshooting sign-in-required messages only. The widget should not reimplement GitHub or Copilot usage APIs when quota-axi already provides normalized output.

  • Copilot auth is commonly stored in ~/.config/github-copilot/apps.json on Linux-style paths.
  • On macOS and other platforms, Copilot-compatible tools may place equivalent app auth data under the user's platform config directory. Let quota-axi own those platform variants.
  • Use local auth checks only to explain why quota-axi cannot authenticate, and only from the server action. Never read auth files from the renderer.

Security Constraints

  • Credential, filesystem, shell, and network access belongs only in extension-owned server actions behind window.babyMenu.capabilities.invoke.
  • Never commit secrets, token dumps, local auth file contents, or captured command output that might include credentials.
  • Do not send Copilot credentials to the renderer. The renderer receives only the normalized snapshot.
  • Keep command stderr out of user-visible errors unless it has been scrubbed for token-like values.

Acceptance Criteria

  • The extension invokes quota-axi --provider copilot --json from copilot-quota/server.ts and parses schema version 2.
  • The server action selects the first providers[] entry with provider: "copilot".
  • The snapshot includes Copilot plan, refreshed time, stale state, sources tried, and all usable windows from live output.
  • percentUsed is treated as used, not remaining, and any label or meter uses one axis consistently.
  • Epoch-zero or otherwise non-useful reset timestamps are omitted rather than rendered as 1970.
  • Missing quota-axi, missing auth, invalid JSON, and timeouts produce explicit unavailable, sign-in-required, or stale results without mock data.
  • No token, cookie, local auth, or credential value is logged, returned, committed, or exposed to the renderer.
  • The implementer verifies the finished server action against real quota-axi output before reporting done.
